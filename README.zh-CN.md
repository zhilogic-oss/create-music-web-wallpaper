# Music Web Wallpaper Builder

[English](README.md) | 简体中文

![Music Web Wallpaper Builder 图标](assets/icon.png)

一个帮助 AI Agent 与用户协作制作 **Wallpaper Engine 音乐网页壁纸**的 Agent Skill。

你可以提供自己拥有使用权的音乐、LRC 歌词、专辑封面、Logo 和设计想法，再通过与 Agent 对话，逐步完成播放器、曲库、同步歌词、主题、动效、设置、多语言和性能优化。你不需要先掌握 HTML、CSS 或 JavaScript，但仍需要参与素材确认、界面选择和 Wallpaper Engine 实机验收。

## 它适合做什么

这个 Skill 不只适用于乐队，也适用于：

- 独立歌手、演唱者与虚拟歌手；
- 作曲者、音乐制作人和其他创作者；
- 游戏、动画或个人音乐收藏；
- 单一专辑、多专辑或按创作者分类的曲库；
- 需要完整播放器、进度调整、动态歌单和歌词解析的 Wallpaper Engine 项目。

对于这类功能，Skill 默认建议制作 **Web 网页壁纸**，而不是 Scene 场景壁纸。

## 主要能力

- 根据用户提供的方向，分阶段设计并调整壁纸界面；
- 整理专辑、曲目、创作者、封面和素材来源信息；
- 辅助匹配音乐文件与歌词文件，并把不确定的匹配交给用户确认；
- 检查封面分辨率、歌词编码与时间戳、重复文件和缺失素材；
- 构建播放、暂停、切歌、进度调整、音量、歌单和随机播放等功能；
- 解析普通 LRC 歌词，并按需要支持原文、翻译或双语显示；
- 按用户选择加入主题、封面动效、模糊背景、频谱、多语言和低占用模式；
- 处理 Wallpaper Engine 属性、状态保存和常见屏幕比例适配；
- 检查素材署名、版权说明、发布结构和基本运行状态；
- 通过与用户反复沟通和实机测试继续微调，而不是一次性套用固定模板。

## 使用前需要准备

尽量准备以下材料：

1. 有权使用的音乐文件；
2. LRC 歌词文件，没有歌词的歌曲也可以加入；
3. 尽可能高清的专辑或单曲封面；
4. 可选的透明 PNG、WebP 或矢量 SVG Logo；
5. 专辑名称、曲目顺序、歌手或创作者信息；
6. 素材作者、来源链接、许可证或授权情况；
7. 喜欢的配色、布局参考和目标屏幕比例；
8. 最终壁纸作者的名称。

优先保留原始素材，不要直接覆盖源文件。准备公开发布时，最终使用的音乐、歌词和图片必须复制进壁纸项目，不能继续引用作者电脑中与项目无关的绝对路径。

## 安装

### 从 GitHub 下载

1. 下载或克隆本仓库：
   `https://github.com/zhilogic-oss/create-music-web-wallpaper`
2. 将整个 `create-music-web-wallpaper` 文件夹放入所用 Agent 支持的 Skills 目录。
3. 确保 `SKILL.md` 位于该文件夹根目录。
4. 重新启动或刷新 Agent，使其重新扫描 Skills。

不同 Agent 的 Skills 目录可能不同，例如 Codex 可使用用户级 Skills 目录，兼容 Agent Skills 标准的客户端也可能使用 `.agents/skills/`。请以所用客户端的官方说明为准。

通过 SkillHub 审核后，也可以从 SkillHub 安装本 Skill。

## 如何开始

安装后，可以直接对 Agent 说：

> 使用 create-music-web-wallpaper，帮我用这些专辑封面、音乐和 LRC 歌词制作一个 Wallpaper Engine 音乐壁纸。先和我确认整体方向，不要立即完成全部功能。

也可以给出更具体的要求：

> 我想为一位独立歌手制作音乐壁纸。曲库分为三张专辑，需要同步歌词、亮暗主题、模糊封面背景和低占用模式。请先检查我的素材质量和文件匹配情况，再制定分阶段计划。

Skill 会优先询问真正影响结果的问题，例如素材路径、创作者分类、歌词形式、视觉风格、目标分辨率、功能范围和壁纸作者，而不是在方向尚未确认时直接进行大规模修改。

## 推荐工作流程

1. **确认方向**：决定创作者、专辑结构、界面风格、歌词语言和功能范围。
2. **检查素材**：核对文件质量、编码、重复项、缺失项和来源信息。
3. **完成最小可用版本**：先让一首歌曲能够播放、调整进度并同步显示歌词。
4. **扩展曲库**：加入其余歌曲、专辑、封面和分类。
5. **逐项调整界面**：依次确认布局、字体、颜色、主题和动效。
6. **优化交互与性能**：明确状态保存、切换逻辑、帧率上限和低占用模式。
7. **在 Wallpaper Engine 中验收**：检查声音、歌词、属性、多语言、不同分辨率和性能。
8. **完善署名后发布**：保证壁纸内可以看到作者、素材来源和必要的版权说明。

不要仅凭普通浏览器中运行正常，就断定 Wallpaper Engine 中的音频、属性回调、本地化和频谱一定正常。

## 歌词处理原则

Skill 默认把导入文件当作普通 LRC：解析时间戳、稳定排序，并显示对应文本。

它**不会默认套用特定项目中的中日双语时间轴重排规则**。只有实际播放证明双语时间轴存在系统性错位，并且用户确认修正规则后，才会加入可撤销的特殊处理。原始 LRC 文件不应被直接覆盖。

当文件名称、LRC 标签、音频元数据和专辑目录给出不同答案时，Agent 应列出可能的匹配并让用户决定，而不是假装已经自动判断正确。

## 附带工具

仓库包含三个辅助脚本：

- `scripts/init_wallpaper.py`：从通用模板初始化一个音乐网页壁纸；
- `scripts/inventory_media.py`：检查媒体文件、歌词、图片尺寸和重复哈希；
- `scripts/validate_wallpaper.py`：检查项目结构、相对路径、曲目数据、署名和发布准备情况。

这些脚本用于提高重复工作的可靠性。通常由 Agent 根据当前环境调用；没有 Python 基础的用户不需要手动修改脚本。

## 可选效果

完成基本播放器后，Agent 会询问你是否希望加入以下内容：

- 封面随鼠标倾斜或上下浮动；
- 模糊封面背景；
- 音频频谱；
- 可拖动、缩放的歌词栏和歌单栏；
- 多语言界面；
- 跟随系统亮暗主题；
- 低占用模式。

这些只是可选方向，不会自动全部加入。是否实现、实现成什么样，应由壁纸制作者决定并通过实际测试调整。

## 这不是什么

- 不是不经沟通即可生成最终作品的一键式程序；
- 不附带受版权保护的示例音乐、歌词、官方封面或 Logo；
- 不会替用户解决第三方素材授权问题；
- 不保证所有文件都能仅凭名称自动准确匹配；
- 不会把 Web 网页壁纸自动转换成 Scene 场景壁纸；
- 不会强制每个项目使用相同布局、颜色或动效。
